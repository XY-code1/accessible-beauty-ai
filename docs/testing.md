## 执行自动化

唯一官方 E2E 验收命令是 `npm run test:e2e`。它使用
`playwright.config.ts` 中统一配置的 Worker 数量；不要通过命令行覆盖并发数。
流程测试会先等待“眼部已定位”且画前照片按钮可用，再进入拍摄步骤；不要用固定等待代替就绪条件。

```sh
npm run test
npm run test:e2e
npm run build
```

浏览器首次安装：`npx playwright install chromium`。可选择本机 Google Chrome：`PW_CHANNEL=chrome npm run test:e2e`。

测试产生的截图/失败追踪在 `test-results/`，不进版本控制。不要把真实用户图片或包含用户画面的追踪文件提交到仓库。

## 真实样本准备（未执行）

先准备 30 对清晰画前/画后样本：10 对调参、20 对验收，**参与者不能跨调参与验收两组**。另外准备至少 10 对未画、模糊或遮挡样本。样本应涵盖目标侧别、眼型与受控光线；保留实际失败案例，不能仅选成功图片。

清晰组需要包含三种方向标签 `close`、`high`、`low`。人工标注应先于算法结果，记录参考路径参数与真实眼尾方向；±10° 内标 `close`，超过 10° 分别为 `high`/`low`。使用同一眼部局部坐标，无法可靠标注的图片进不可判断组。边界样本另行备注，避免按模型结果反向修改标签。

在 `samples/private/` 放置图片与清单（该目录已忽略）。清单结构：

```json
{
  "samples": [
    {
      "id": "p01-01",
      "participant": "p01",
      "split": "tune",
      "label": "close",
      "before": "p01/before.jpg",
      "after": "p01/after.jpg",
      "side": "right",
      "angle": 20,
      "length": 0.3
    }
  ]
}
```

`split` 为 `tune`、`acceptance`、`unusable`；最后一组的 `label` 必须为 `unknown`。图片必须为原始摄像头画面，不能包含参考线或镜像后的截图。参与者使用匿名编号；图片文件相对清单路径解析。

执行：

```sh
npm run test:vision -- samples/private/manifest.json
```

本机脚本启动仅监听 `127.0.0.1` 的临时服务，通过真实 MediaPipe 提取每张图片的眼部位置，然后调用应用同一套 OpenCV 分析。每张静态照片使用独立检测器，避免不同人之间的时间跟踪状态串入。报告写到清单旁的 `report.json`，不包含原始图片。`durationMs` 是方向检查耗时，`pipelineMs` 包括图片、模型初始化等整条样本通路耗时，不代表实时跟踪帧率。

报告记录：

- 判断覆盖率 = 清晰验收样本中给出确定方向的数量 / 清晰验收样本总数。
- 拒判率 = 1 − 判断覆盖率。
- 条件正确率 = 正确的确定判断数 / 确定判断总数（无确定判断记为 0）。
- 不可判断组错误输出确定方向的数量，以及逐对耗时/原因。

通过门槛：调参至少 10 对、验收至少 20 对；清晰组覆盖率 ≥80%（20 对中至少 16 对），给出判断的结果正确率 ≥90%；不可判断组至少 10 对，全部不输出确定方向。新增更多样本时按相同比例计算。门槛是本次受控 Demo 的实验标准。

如果失败：记录失败类别，回到**调参组**调整规则，固定新版本，再使用新的独立验收集。不能反复在同一验收集调参后继续称其为独立验收。
