演示地址（待部署成功后可用）：<https://xy-code1.github.io/accessible-beauty-ai/>

## 自动验证边界

自动检查使用 Chromium 的合成摄像头，只证明 HTTPS 页面可调用摄像头 API并能加载本地模型资源。下列项目均为**待人工执行**：真实摄像头授权、实体手机性能、真人眼部定位、移动 Safari 行为和美妆准确率。

## 测试前准备

1. 先确认 GitHub Pages 来源为 GitHub Actions，且最新 main 对应的 Deploy mobile demo 中 build、deploy、verify 均成功，再用手机浏览器直接打开上述 HTTPS 地址，不要使用应用内网页预览。
2. 记录机型、系统和浏览器完整版本，关闭可能占用摄像头的其他应用。
3. 首次打开时清除该站点缓存，使用秒表记录首次加载和模型就绪时间。
4. 只使用自愿参与者；不要把真人照片、录屏或包含人脸的追踪文件提交到仓库。

## 每轮操作

1. 首次打开首页，确认无白屏；刷新一次，再直接打开演示地址下的 `#/eyeliner`（保留 `/accessible-beauty-ai/` 前缀）。
2. 点击“开启摄像头”，选择允许，记录从点击到“眼部已定位”的时间。
3. 先用“仅跟随指引练习”完成两步，确认基本流程正常；重新开始后再完成画前照片及两次检查，分别记录失败提示、卡顿和恢复方法。
4. 分别测试“关闭摄像头”、完成练习和返回工作台，确认系统摄像头指示消失。
5. 拒绝一次权限，再从浏览器站点设置恢复授权，记录完整复现步骤。
6. iPhone 额外测试 Safari 前后台切换、锁屏恢复和屏幕旋转。

失败记录至少包含：机型、系统、浏览器版本、网络、发生步骤、连续操作、可见提示、能否恢复以及复现次数。真人识别、性能或准确率只能根据实际记录结论，不能由自动部署检查推断。
